# Windows + WSL2で実行する

**日本語** | [English](windows-wsl2_en.md)

`setup.cmd`からセットアップと動画・音声作成を始められます。

## 1. セットアップを始める

GitHubの **Code > Download ZIP** からZIPを取得して展開し、`setup.cmd`をダブルクリックしてください。

初回に用途を選びます。

- **音声作成だけ**: CPUでも利用できます。
- **動画生成も使う**: NVIDIA GPUが必要です。構成ごとの必要メモリや空き容量は、後の準備画面で確認できます。

ウィザードの案内に沿って、Ubuntu、WSL2、Docker Desktopを準備します。インストールや設定変更の前には確認が表示されます。
WindowsのNVIDIAドライバーが必要な場合は、表示される公式ページから導入してください。

Ubuntuの初回画面ではLinux用のユーザー名とパスワードを作成します。パスワード入力中は文字が表示されません。
`user@computer:~$`のような表示になったら、`exit`と入力してEnterを押してください。

Docker Desktopの初回画面が開いたら、利用条件を確認してDashboardまで進み、セットアップ画面へ戻ってEnterを押してください。
WSL統合が必要な場合は、ウィザードから有効化できます。

動画用の初期WSL設定は、メモリ20 GiB・swap 32 GiBです（すでに大きい値を設定している場合はそのまま使います）。準備画面で720pを選ぶと、現在のswapと48 GiBの必要値を表示し、増やすか確認します。同意すると`.wslconfig`をバックアップして更新し、選んだ720pの準備を再開します。設定反映時はすべてのWSLディストリビューションとDockerコンテナを停止するため、作業を保存してから続行してください。

UbuntuとWSL2の導入前にデスクトップショートカットの作成を確認します。再起動を案内されたら、デスクトップの **Narration Video Gen** を開くと続きから進めます。
ショートカットを作成しなかった場合は、同じ`setup.cmd`を開いてください。セットアップ完了時にもショートカットを作成できます。

## 2. 動画・音声を作る

動画用途では、セットアップ後に動画生成メニューが開きます。

1. **キャラクターと音声を作る**でWeb UIを開き、キャラクターの画像・声・話し方と台本を設定します。音声を確認したら、**この音声を動画の入力にする**を押します。
2. **動画の構成選択と準備**で、モデルと解像度を選び、モデルと実行イメージを準備します。720pに必要なswapが不足している場合は、ここで48 GiBへの変更確認が表示されます。
3. **動画を生成**で、Web UIから作成した入力セットを選んで生成します。初回は短尺テストを使ってください。
4. **生成状況を確認**で、進捗と完成動画の保存先を確認します。

生成はバックグラウンドで続きます。ウィンドウを閉じた後も、同じショートカットから進捗確認や中止ができます。
素材の置き方や詳しい操作は[Linux手順書の生成手順](linux.md#3-素材を選んで生成する)を参照してください。

動画用途の**キャラクターと音声を作る**、または音声用途では、ブラウザで音声作成ページが開きます。自動で開かない場合は、表示された`http://127.0.0.1:7861`をWindowsのブラウザへ入力してください。

用途を変更する場合は、`setup.cmd`があるフォルダのPowerShellで次のいずれかを実行します。

```powershell
.\setup.cmd -Purpose Tts
.\setup.cmd -Purpose Video
```

選択は保存され、次回からも使われます。デスクトップショートカットを作成済みなら、`setup.cmd`は`%LOCALAPPDATA%\NarrationVideoGen`にもあります。

## メモリと保存先

| 構成 | 物理RAM | WSL RAM | swap |
|---|---:|---:|---:|
| 480p | 32 GiB | 20 GiB | 32 GiB |
| 720p Wan 2.2 | 24 GiB | 16 GiB | 48 GiB |
| 720p Wan 2.1 | 32 GiB | 20 GiB | 48 GiB |

WSLのメモリやswapを増やしても、物理RAMの要件は変わりません。利用できる構成は準備画面に表示されます。

実行用リポジトリはWSL内の`~/narration-video-gen`へ配置されます。モデルや出力もここに保存されます。

動画の生成が正常に完了すると、最終動画だけがWindowsの
`ビデオ\Narration Video Gen\<実行ID>\video.mp4`にも自動でコピーされます。
生成途中のファイルとWSL側の原本は`~/narration-video-gen/outputs`に残るため、
Windows側へのコピーに失敗しても生成結果は失われません。
Windowsから見るには、エクスプローラーの **Linux > 使用するUbuntu > home > ユーザー名 > narration-video-gen** を開いてください。

## 容量を解放する

動画生成メニューの **容量を解放する (cleanup)**、または`cleanup.cmd`を開くと、
ダウンロード済みモデル、Narration Video Genが作成した
Dockerイメージ、WSL仮想ディスクの縮小を個別またはまとめて実行できます。
削除せず対象と容量だけを確認する場合は、PowerShellで`.\cleanup.cmd -Check`を実行します。

入力素材、生成動画、設定、キャラクター、Dockerボリューム、他プロジェクトのイメージは削除しません。
WSL仮想ディスクの縮小ではDocker DesktopとすべてのWSLディストリビューションを停止するため、
別途確認と管理者権限が必要です。縮小すると、セットアップが`.wslconfig`に追加した
`memory=20GB`と`swap=32GB`も削除します。動画用セットアップを再実行すると再設定できます。

モデル取得前の空き容量はWan 2.1で55 GiB、Wan 2.2で80 GiBが目安です。WSLのswap領域も別途必要です。
モデル読み込みが遅くなるため、実行用リポジトリを`/mnt/c`などのWindowsドライブへ移さないでください。

## 問題が起きたとき

まず`setup.cmd`を再実行し、表示された未完了の項目を確認してください。設定を変更せず確認する場合:

```powershell
.\setup.cmd -Check -Purpose Video
# 音声用途なら -Purpose Tts
```

Dockerを利用できない場合は、Docker Desktopを起動し、**Settings > Resources > WSL Integration**で使用するUbuntuを有効にしてください。
WindowsのPowerShellで`wsl --list --verbose`を実行すると、ディストリビューション名とWSLのバージョンを確認できます。

特定のUbuntuを使う場合は、表示された名前を指定します。

```powershell
.\setup.cmd -Distribution Ubuntu-24.04
```

WSL側のCLIの表示言語は、通常のセットアップ時にWindowsの表示言語に合わせて保存されます。
一時的に変更する方法は[Linux手順書の表示言語](linux.md#表示言語を変える)を参照してください。

詳しい対処方法は[トラブルシューティング](../troubleshooting.md)を参照してください。
